# vocab-study

능률VOCA 단어 학습 웹앱. 정적 HTML 두 개로 동작합니다.

- `index.html` — 학생용 (플래시카드 · 객관식 퀴즈(6지선다) · **주관식 퀴즈** · 단어장 · 즐겨찾기)
- `admin.html` — 선생님용 (학생별 즐겨찾기 · 틀린 단어 · 주관식 인정 답안 관리)
- `supabase/functions/judge-meaning/` — (선택) AI 채점용 Edge Function
- `setup-ai.sh` — AI 채점 켜기 (키 등록 + 함수 배포를 한 번에)

## 주관식 퀴즈 (뜻 직접 입력)

학생이 단어의 뜻을 직접 입력하면, **표준 답안과 글자가 달라도 뜻이 통하면 정답으로 인정**합니다.
채점은 100% 브라우저 안에서 이루어지며 **외부 API(구글 번역·검색 등)를 쓰지 않습니다.**
그래서 무료이고, 인터넷이 느려도 즉시 채점되며, API 키가 노출될 위험도 없습니다.

채점 방식은 `index.html` 안의 "주관식 채점기" 블록에 들어 있고, 다음을 조합합니다.

1. **정규화** — 공백·문장부호·괄호 주석·`~을/를` 같은 자리표시를 지웁니다. (`포기 하다.` = `포기하다`)
2. **뜻 분리** — 쉼표로 나열된 뜻은 각각 정답으로 인정합니다. (`버리다, 포기하다` → 둘 중 하나만 써도 정답)
3. **어간 추출** — 어미·조사를 벗겨 비교합니다. (`버림`·`버리다`·`버려서` → `버리`)
4. **동의어 사전** — 뜻 묶음 약 350개. (`포기하다` ↔ `단념하다` ↔ `그만두다`, `나중에` ↔ `추후에`)
5. **자모 편집거리 / 바이그램** — 오타를 흡수합니다. (`정확환` → `정확한`)
6. **오답 방지** — 같은 범위의 *다른 단어*의 뜻을 더 정확히 적었으면 오답 처리합니다.

판정 결과는 세 가지입니다.

| 판정 | 기준 | 화면 |
|---|---|---|
| ❌ 품사 오답 | 품사가 다름 | 어떤 품사로 써야 하는지 알려 줌 (AI 호출 없음) |
| ❌ 제외된 뜻 | 문제에 `(…x)` 로 빼라고 한 뜻 | 그 뜻은 쓰지 말라고 알려 줌 (AI 호출 없음) |
| ⭕ 정답 | 유사도 0.86 이상 | 바로 정답 처리 |
| 🤔 비슷함 | 0.60 ~ 0.86 | 모범답안을 보여 주고 학생이 `같은 뜻이에요 / 다른 뜻이었어요`를 직접 고름 |
| ❌ 오답 | 0.60 미만 | 모범답안 표시 + `선생님께 인정 요청` 버튼 |

기준값은 `index.html`의 `const ACCEPT=0.86, GRAY=0.60;` 에서 조절할 수 있습니다.
숫자를 낮추면 더 후하게, 높이면 더 엄격하게 채점합니다.

### 품사는 예외 없이 엄격하게

뜻이 통해도 **품사가 다르면 오답**입니다.

| 단어 | 답 | 판정 |
|---|---|---|
| `acquire` (동) | 획득하다 | ⭕ |
| `acquire` (동) | 획득 | ❌ 명사라서 |
| `abstract` (형) | 추상적인 | ⭕ |
| `abstract` (형) | 추상 | ❌ 명사라서 |
| `burden` (명) | 짐 | ⭕ |
| `burden` (명) | 부담스럽다 | ❌ 형용사라서 |

`~다` 로 끝나거나 `~한/~인/~하는`, `~하자면/~하면/~으면/~되어` 같은 어미가 붙으면
용언(동사·형용사), 아니면 체언(명사)으로 봅니다.
`을`·`를`·`이`·`가`·`의`·`에` 로 끝나면 **명사(체언)로만** 봅니다.
그래서 `핵심적인 역할을 하다` 문제에 `핵심적인 역할을` 이라고 쓰면 품사 오답입니다.
(`은`·`는` 만 양쪽으로 둡니다 — `넓은` 은 형용사, `짐은` 은 명사+조사이기 때문입니다)

교재 뜻이 명사이면 **답이 조사로 끝나기만 해도 오답**입니다 — `edge`(가장자리) 에
`모서리는` 이라고 쓰면, `모서리` 가 사전에 있는 뜻이라도 조사 때문에 막힙니다.
`차이`·`정의`·`회의` 처럼 조사처럼 끝나는 두 글자 명사는 잘못 잡지 않습니다.

교재의 뜻에 **조사만 덧붙인 답은 오답**입니다 — `기회` 가 뜻인데 `기회의`,
`기회를` 이라고 쓰면 "조사 ‘의’를 빼고 ‘기회’라고 써 주세요" 라고 알려 줍니다.
조사를 뗀 형태가 교재의 뜻과 **정확히 같을 때만** 잡으므로,
`폭넓은`(넓은의 유의어) 처럼 우연히 조사로 끝나는 답은 걸리지 않습니다.

품사는 체언(명사) · 용언(동사·형용사) · **부사** 세 갈래로 봅니다.
`순간적인`(관형)과 `순간적으로`(부사)는 다른 품사이므로, `momentary`(순간적인) 에
`순간적으로` 라고 쓰면 오답입니다 — 그건 momentarily 의 뜻입니다.
(`~적으로` · `~하게` · `~스럽게` · `~히` 로 끝나면 부사로 봅니다)

`포함`·`버림`·`얻음` 같은 **명사형은 체언**입니다 — `포함하다` 문제에 `포함` 이라고
쓰면 오답입니다. (`화면`·`사고`·`측면` 처럼 생김새가 비슷한 진짜 명사는 그대로 명사로 봅니다.) `짐은`·`능력이` 처럼 조사가 붙어 애매한 경우는
양쪽 다 가능한 것으로 보아 억울한 오답을 만들지 않습니다.

### 어간 비교는 왜 남겨 두었나

`기회의` 가 정답으로 처리되던 문제 때문에 "어간 비교를 아예 빼는 게 낫지 않나"
검토했습니다. 실제로 재 보니 **빼면 손해**였습니다.

| | 교재뜻 | 활용형 | 유의어 | 조사 거부 | 명사형 거부 |
|---|---|---|---|---|---|
| 현재 | 631/631 | **301/304** | 10/10 | 268/268 | 79/80 |
| 어간 비교 제거 | 631/631 | **114/304** | 10/10 | 268/268 | 78/80 |
| 어간+동의어 제거 | 631/631 | 6/304 | 0/10 | 268/268 | 78/80 |

조사 문제는 어간과 무관하게 이미 다 잡힙니다(조사 검사가 잡음).
어간을 빼면 `간과했다`·`간과하는` 같은 정상 답 **187개가 오답**이 되고,
얻는 것은 명사형 1건뿐입니다. 그래서 어간 비교는 두고, 대신 **빠져나가는
구멍을 막는 쪽**으로 갔습니다 — 품사 검사, 조사 검사, 아래의 조사 분류 좁히기.

> 재현: `node exp-stem.js` (scratchpad) — 세 가지 설정을 같은 데이터로 비교합니다.

### 교재에 없는 품사라도 사전에 있으면 인정

교재에 한 품사만 적혀 있어도, **그 단어가 사전에서 다른 품사로도 그 뜻을 가지면 정답**입니다.
이 판단은 AI 가 합니다 (규칙만으로는 알 수 없습니다).

> `demand` 의 교재 뜻이 "요구, 다급히 처리해야 할 일"(명사) 뿐이어도,
> 사전에 동사 "요구하다" 가 있으므로 **"요구하다" 는 정답**입니다.

사전에도 그런 품사·뜻이 없으면 오답입니다.

| 단어 | 교재 뜻 | 답 | 판정 |
|---|---|---|---|
| demand | 요구 (명) | 요구하다 | ⭕ 사전에 동사 뜻이 있음 |
| acquire | 얻다 (동) | 획득 | ❌ 명사로 쓰이지 않음 |
| atom | 원자 (명) | 원자이다 | ❌ |
| in summary | 요약하자면 | 요약 | ❌ |

한 번 인정된 답은 저장되어 **다음부터는 API를 부르지 않습니다.**
AI 를 쓸 수 없을 때(주소 미설정·서버 장애)는 예전처럼 엄격하게 오답 처리합니다.

품사가 틀리면 **AI에게 묻지 않고 바로 오답**입니다 (호출 비용도 들지 않습니다).
**학생이 "같은 뜻이에요"로 정답 처리할 수 없습니다** — 자가 판단 버튼이 나오지 않습니다.
AI 가 품사·형태 문제라고 판정한 경우(`pos`)도 마찬가지로 바로 오답입니다.

뜻 자체가 아예 다른 답은 "품사" 가 아니라 그냥 오답으로 처리합니다.
품사 안내는 **뜻이 통하는데 형태만 다를 때만** 나옵니다.

`p` 를 적어 두지 않았으면 품사 이름 대신 모범답안의 형태를 보여 줍니다
(`in summary` = "요약하자면" 에 "요약" 이라고 쓰면 → "‘요약하자면’ 처럼 같은 형태로 써야 해요").

교재의 뜻에 `포함[수반]하다` 처럼 대괄호로 대안이 적혀 있으면 양쪽 모두 정답입니다
(`포함하다` · `수반하다`).
학생에게는 "acquire 는 동사예요. ‘~하다’처럼 동사로 써 주세요" 라고 알려 줍니다.
주관식 문제 화면에도 품사를 함께 보여 줍니다.

동사와 형용사는 서로 구분하지 않습니다 (둘 다 용언). 그 경우는 뜻 점수에서 걸러집니다.

### 사전에 있는 뜻이면 지엽적인 뜻도 인정

교재에 안 적혀 있어도 **사전에 실린 그 단어의 뜻이면 정답**으로 봅니다.
규칙·사전으로 못 잡으면 AI 가 판단합니다.

> `address` 의 교재 뜻이 "다루다, 처리하다" 뿐이어도, 학생이 "연설하다" 라고 쓰면 정답입니다.

### 특정 뜻을 빼고 답하게 하기 — `단어(뜻x)`

문제에 쓰지 말아야 할 뜻을 괄호에 적고 `x` 를 붙입니다.

```js
{w:"Address(주소x)", p:"동", m:"다루다, 처리하다"},
{w:"record(기록x, 기록하다x)", p:"명", m:"음반, 레코드"},
```

- 학생 화면에도 `Address(주소x)` 그대로 보여 줘서, 무엇을 빼야 하는지 알 수 있습니다.
- 그 뜻을 쓰면 **AI 에게 묻지 않고 바로 오답**입니다.

### 품사를 지정하기 — `단어(v)`

```js
{w:"address(v)", m:"다루다, 처리하다"},      // 동사 뜻만 인정
{w:"record(n)",  m:"음반, 기록"},            // 명사 뜻만 인정
```

괄호에 `v`(동) · `n`(명) · `adj`(형) · `adv`(부) — 또는 `동`/`명`/`형`/`부` — 를 적으면
**그 품사의 뜻만** 정답입니다. 지정된 단어는 사전에 다른 품사가 있어도 인정하지 않고,
AI 도 부르지 않습니다. 제외 표기와 함께 쓸 수 있습니다: `address(v, 주소x)`.
학생 화면에는 표기가 그대로 보이고 문제 아래에 품사도 표시됩니다.

지정하지 않은 단어는 **사전에 실재하는 품사의 뜻이면 모두 인정**합니다
(address → 주소·연설하다·다루다·말을 걸다).

### 글자가 전혀 다른 동의어 — `alt` 로 해결

`나중에`와 `추후에`처럼 **글자가 하나도 겹치지 않는** 동의어는 편집거리·어간으로는
절대 잡을 수 없습니다. 뜻이 같다는 건 글자가 아니라 의미의 문제이기 때문입니다.
그래서 두 가지 장치를 둡니다.

**(1) 단어별 추가 정답 `alt`** — 가장 확실한 방법입니다.

```js
{w:"subsequently", p:"부", m:"그 뒤에, 나중에", alt:"추후에, 이후에, 뒤이어"},
```

`alt` 에 적은 표현은 뜻(`m`)과 똑같이 **100% 정답**으로 처리됩니다.
사전마다 뜻풀이가 달라 학생이 다르게 쓸 만한 단어에만 붙이면 됩니다.

**(2) 동의어 사전** — `SYN_GROUPS` 에 들어 있는 묶음은 모든 단어에 자동 적용됩니다.
시간·빈도·정도 부사, 접속어, 자주 쓰는 동사/형용사/명사를 넣어 두었습니다.

> 참고: 뜻이 다른 말은 여전히 오답입니다. 예를 들어 `subsequently` 에 `따라서`라고
> 쓰면 오답이고, 같은 범위에 `consequently` 가 있으면 "이 답은 consequently 의
> 뜻이에요"라고 알려 줍니다. 반대로 같은 범위의 다른 단어와 뜻이 겹치는 답
> (`achieve` 에 `달성하다`)은 "비슷함"으로 두어 학생이 직접 판단하게 합니다.

### 인정 답안이 쌓이는 방식

- 학생이 "비슷함" 구간에서 스스로 인정한 답 → 그 학생에게만 다음부터 자동 정답 (`kind: alias`)
- 오답 화면에서 보낸 인정 요청 → 선생님 확인 대기 (`kind: alias_req`)
- `admin.html` → 학생 → **✍️ 주관식 인정 답안** 탭에서 `전체 인정`을 누르면
  그 답이 **모든 학생**에게 정답으로 인정됩니다.

Supabase `progress` 테이블을 그대로 쓰며 스키마 변경은 필요 없습니다.
공통 인정 답안은 `student_key = "__ALIAS__"` 인 가상 계정 행으로 저장됩니다.

### 동의어를 더 넣고 싶다면

특정 단어에만 필요하면 `alt` 를, 모든 단어에 두루 쓰이는 말이면
`index.html`의 `SYN_GROUPS` 배열에 한 줄 추가하면 됩니다.

```js
["기부하다","기증하다","내놓다","희사하다"],
```

## AI 채점 (선택) — 사전에 없는 표현까지

`alt` 와 동의어 사전으로도 모든 경우를 미리 적어 둘 수는 없습니다.
그래서 **규칙으로 "비슷함/오답"이 나온 답만** AI에게 한 번 더 물어보는 단계를 둡니다.

```
학생 답안 → 규칙·사전 채점 ─ 정답 ─────────────────→ 정답 (AI 호출 없음)
                          └ 비슷함/오답 → AI 판정 → 정답 / 비슷함 / 오답
```

- **규칙으로 정답이 난 답은 AI를 부르지 않습니다.** 대부분의 답이 여기서 끝납니다.
- AI가 인정한 답은 **모든 학생에게 공유 저장**되어, 같은 답은 두 번 다시 묻지 않습니다.
  쓸수록 호출이 줄어듭니다.
- AI 서버가 죽거나 느리면(9초) **조용히 규칙 판정으로 되돌아갑니다.** 수업이 멈추지 않습니다.
- 선생님은 `admin.html` 목록 화면의 **🤖 AI가 인정한 답안** 패널에서 확인하고 지울 수 있습니다.
  지우면 공유본과 **모든 학생의 개인 기록까지** 함께 사라집니다.
  **채점 규칙(프롬프트)을 바꾼 뒤에는 [전체 비우기]를 한 번 누르세요** — 예전 규칙으로
  잘못 인정된 답이 남아 있으면 새 규칙과 무관하게 계속 정답 처리되기 때문입니다.
  즐겨찾기·틀린 단어에는 영향이 없습니다.

API 키는 브라우저에 두면 그대로 노출되므로, Supabase Edge Function 안에 숨깁니다.

보고되고 있습니다. 아래 자체 점검에서 바로 확인할 수 있고, 그 경우 AI Studio 에서
키를 다시 발급하거나 다른 프로젝트의 키를 쓰면 됩니다.

### 채점 테스트 (관리 화면)

`admin.html` 명단 화면의 **🧪 채점 테스트**에서 원하는 단어·뜻·답을 넣어
AI 판정을 바로 볼 수 있습니다. 퀴즈에 그 단어가 나오길 기다릴 필요가 없습니다.
`(v)` 품사 지정과 `(주소x)` 제외 표기도 그대로 동작합니다.

**[검증 세트 실행]** 버튼은 확인용 5건(orbit·demand·offer·less than·momentary)을
한 번에 돌려 "5 / 5 통과" 여부를 보여 줍니다 — 프롬프트를 바꿔 재배포할 때마다
이 버튼으로 확인하면 됩니다.

이 테스트는 AI 판정만 봅니다. 교재 뜻과 글자가 똑같은 답이나 조사만 붙인 답은
학생 화면에서 AI 없이 먼저 걸러집니다.

### 자체 점검

배포한 함수가 실제로 Gemini 를 부를 수 있는지 앱을 켜지 않고 확인할 수 있습니다.
(`setup-ai.sh` 는 배포 직후 이걸 자동으로 실행합니다.)

```bash
curl -H "Authorization: Bearer <index.html 의 SUPABASE_ANON 값>" \
     "https://uxzsleryzpjaoqciyqvs.supabase.co/functions/v1/judge-meaning?selftest=1"
```

정상이면 이렇게 나옵니다.

```json
{"ok":true,"message":"AI 채점이 정상 동작합니다.","keyType":"AQ (신형 인증 키)",
 "model":"gemini-2.5-flash-lite","auth":"bearer",
 "sample":{"answer":"추후에","verdict":"correct","reason":"..."}}
```

선택 환경변수:

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_MODEL` | `gemini-2.5-flash-lite` | 다른 모델을 쓰고 싶을 때 |
| `ALLOWED_ORIGIN` | `*` | CORS 허용 도메인 제한 |

모델 이름이 바뀌어 실패하면 `gemini-2.0-flash-lite` → `gemini-2.5-flash` 순으로
자동 재시도하므로 갑자기 채점이 멈추지는 않습니다.

### 비용

Gemini 2.5 Flash-Lite 기준 입력 $0.10 / 출력 $0.40 per 1M tokens.
한 번 채점에 입력 약 250 · 출력 약 40 토큰이므로 **1건에 약 0.00004달러(0.06원)** 입니다.
게다가 무료 티어가 **분당 15건 · 하루 1,000건**이라, 웬만한 학원 규모는 무료 범위 안에서 끝납니다.
(규칙으로 정답이 난 답은 호출 자체를 하지 않고, 한 번 인정된 답은 재호출하지 않습니다.)

### 안전장치

- API 키는 Edge Function 환경변수에만 있고 브라우저로 내려가지 않습니다.
- 함수는 채점 전용입니다. 프롬프트가 고정이고 출력이 `{verdict, reason}` JSON 스키마로
  묶여 있으며 최대 출력이 120 토큰이라, 일반 챗봇처럼 악용하기 어렵습니다.
- 답안 80자, 뜻 300자로 길이를 자릅니다.

## 학생 명단 (입장 제한) — 성적 사이트와 공유

입장 확인은 **성적 사이트(score-system)의 학생 명단**을 그대로 씁니다.
학생은 성적 사이트와 **똑같은 이름 + PIN(학부모님 연락처 뒷 4자리)** 으로 들어옵니다.

명단을 복사해 오지 않습니다. score-system 은 `students` 표를 anon 에 열지 않고
`parent-login` Edge Function 으로만 검증하는데, vocab-study 의 `student_login` 이
그 함수를 그대로 호출합니다.

- 명단이 갈라지지 않습니다. 성적 사이트에서 학생을 넣거나 빼면 **즉시** 반영됩니다.
- score-system 의 데이터는 **읽지도 쓰지도 않습니다.** 로그인 확인만 합니다.
- 새 키가 필요 없습니다. 이미 공개된 anon 키만 쓰고, 그것도 서버(`app_config`)에만
  두어 브라우저로 내려가지 않습니다.
- 성적 사이트가 응답하지 않으면 수업이 끊기지 않도록 통과시킵니다.
  막고 싶으면 `index.html` 의 `STRICT_ROSTER` 를 `true` 로 바꾸세요.

### 학생 관리 — 성적 사이트 명단을 그대로 고칩니다

`admin.html` → **[👥 명단 관리]** 는 성적 사이트(score-system)의 학생 명단을
**직접 읽고 고칩니다.** 여기서 바꾸면 성적 사이트에도 그대로 반영됩니다.
화면 구성은 성적 사이트와 같습니다.

- **학생 추가** — 이름 / PIN(학부모 연락처 뒷 4자리) / 학부모 연락처 / 학생 연락처 / 반
- **학생 목록 · 검색** — 반으로 고르거나 이름으로 전체 검색
- **바로 수정** — 이름 · PIN · 연락처 · 특이사항을 칸에서 고치고 다른 곳을 누르면 저장
- **퇴원 / 복귀**, **반 이동**

score-system 은 `students` 표를 anon 에 열지 않고 `admin-api` Edge Function 으로만
다룹니다. 그래서 vocab-study 도 같은 함수를 쓰고, **성적 사이트 관리자 번호**를
한 번 입력받습니다.

> 번호는 **메모리에만** 두고 저장하지 않습니다. 화면을 벗어나거나 창을 닫으면 지워지고,
> 다시 들어가면 다시 물어봅니다. (성적 사이트 관리 화면과 같은 방식입니다)

**학생 지우기는 넣지 않았습니다.** 성적·출결까지 함께 사라질 수 있어서,
삭제는 성적 사이트에서 하시도록 남겨 두었습니다. 필요하면 추가할 수 있습니다.

성적 사이트 명단에 **없는** 학생(예: 김채현)은 같은 화면 아래
**[따로 허용한 학생]** 에 넣으면 단어 사이트에서만 입장할 수 있습니다.

> **⚠ SQL 을 적용하기 전에는 예외를 추가하면 안 됩니다.**
> 예전 `student_login` 은 "예외 명단이 비어 있으면 전원 통과, 하나라도 있으면
> 명단에 있는 사람만" 이었습니다. 그래서 이 상태에서 예외를 한 명 넣으면
> **나머지 학생 전원이 로그인할 수 없게 됩니다.** (실제로 한 번 겪었습니다.)
>
> 관리 화면이 이 상태를 스스로 알아채서 빨간 경고를 띄우고 예외 추가를 막습니다.
> 판별은 `student_login` 이 `reason: "open"` 을 돌려주는지로 합니다 — 예전 함수만
> 그 값을 씁니다. SQL 을 적용하면 경고가 사라지고 잠금이 풀립니다.

### 예전 방식 (참고)



예전에는 **아무 이름이나 넣어도 입장**할 수 있었습니다. 이름을 잘못 쓰면 그 학생의
학습 기록이 갈라지고, 명단에 없는 사람도 들어올 수 있었습니다.

이제 `admin.html` → 상단 **[👥 명단 관리]** 에서 등록한 학생만 입장할 수 있습니다.

- **명단이 비어 있으면 예전처럼 누구나 입장합니다.** (등록 전에 전원이 잠기는 사고 방지)
  이 상태에서는 관리 화면에 노란 경고가 표시됩니다.
- **학생을 한 명이라도 추가하면 그때부터 명단 확인이 켜집니다.**
- `[기존 학습 기록에서 가져오기]` 를 누르면 이미 기록이 있는 학생을 한 번에 등록합니다.
- 이름의 공백은 무시합니다 (`권 혁` = `권혁`). 명단에 적힌 이름으로 표시됩니다.
- 명단에서 지워도 **학습 기록은 남습니다.** 입장만 막힙니다.

확인은 서버 함수(`student_login`)가 합니다. `students` 표는 RLS 로 잠겨 있어
브라우저에서 직접 조회할 수 없고, 이 함수를 통해서만 "맞다/아니다"를 돌려받습니다.

서버에 연결되지 않을 때는 수업이 끊기지 않도록 통과시킵니다.
연결이 끊겼을 때도 막고 싶으면 `index.html` 의 `const STRICT_ROSTER = false;` 를
`true` 로 바꾸세요.

> 참고: 이름과 뒷 4자리를 아는 사람이 그 학생으로 입장하는 것까지는 막지 못합니다.
> 거기까지 막으려면 학생별 비밀번호가 필요합니다.

## 데이터베이스 메모

`students` 표와 명단 관련 함수는 마이그레이션 `student_roster` 로 만들어져 있습니다.
(`student_login`, `roster_list`, `roster_add`, `roster_remove`, `roster_seed_from_progress`)

`progress` 테이블은 이미 아래 조건을 만족하므로 스키마 변경 없이 동작합니다.

- `UNIQUE (student_key, kind, word_id)` — 인정 답안 저장(upsert)에 필요
- `kind` 에 CHECK 제약이 없어 `alias` / `alias_req` / `alias_ai` 가 그대로 들어감
- 모든 열이 `text` 라 길이 제한 문제 없음

한 가지 선택 사항: RLS 에 **UPDATE 정책이 없습니다.** SELECT · INSERT · DELETE 만 있어서,
이미 있는 행을 다시 upsert 할 때(같은 답을 두 학생이 동시에 인정받는 경우 등)
조용히 실패합니다. 앱이 메모리에서 중복을 걸러 주기 때문에 실제로 문제가 되는 일은
드물지만, 깔끔하게 하려면 **SQL Editor** 에서 한 줄 실행하면 됩니다.

```sql
create policy "anon can update" on public.progress for update using (true) with check (true);
```

(DELETE 와 INSERT 가 이미 열려 있으므로 보안 수준이 달라지지는 않습니다.)

## 퀴즈는 언제나 20문제

범위를 아무리 넓게 잡아도 퀴즈는 **20문제**만 나옵니다. 챕터 1개(23단어)든
전체(573단어)든 같습니다. 매번 범위 안에서 새로 20개를 무작위로 뽑으므로,
`다시 풀기` 를 누르면 대부분 다른 단어가 나옵니다.

문제 수는 `index.html` 의 `const QUIZ_LEN = 20;` 에서 바꿉니다.

객관식 **오답 보기는 고른 범위 안에서만** 뽑습니다. 범위 전체에서 뽑으면
고르지 않은 챕터의 뜻이 섞여 문제가 너무 쉬워집니다.
(범위가 6개 미만일 때만 그룹 전체에서 채웁니다)

## 즐겨찾기 · 틀린 단어 재시험

- **즐겨찾기** — 별표한 단어 목록 위에 `객관식 재시험` / `주관식 재시험` 버튼이 있습니다.
  현재 고른 범위 안의 즐겨찾기만 모읍니다. 별표를 다시 누르면 목록에서 빠집니다.
- **틀린 단어** — 퀴즈에서 틀린 단어가 자동으로 쌓입니다(범위와 무관하게 전체).
  같은 방식으로 재시험을 볼 수 있고, 다 외운 단어는 `제외` 버튼으로 목록과 기록에서
  지웁니다. 제외는 이 학생에게만 적용되고, 다시 틀리면 다시 쌓입니다.
- **2번 연속 맞히면 자동 제외** — 어떤 퀴즈에서든 틀린 단어를 두 번 연속 맞히면
  목록에서 자동으로 빠집니다. 중간에 한 번이라도 틀리면 연속이 끊겨 처음부터 다시
  셉니다. 한 번 맞힌 단어는 목록에 `✓ 1/2` 로 표시됩니다.
- 객관식 재시험은 단어가 6개(보기 수) 이상일 때만 열립니다. 그 미만이면 주관식으로 보세요.
- 재시험도 20문제 제한이 그대로 적용됩니다.

## 여러 챕터를 한 번에

범위 선택 화면에서 챕터를 **여러 개 눌러 고를 수 있습니다.** 고른 개수와 단어 수가
아래 막대에 뜨고, `선택한 범위로 공부하기` 를 누르면 그 챕터들을 합쳐서
플래시카드 · 퀴즈 · 단어장으로 씁니다. (`교과서 1-1 외 2개 · 73단어` 처럼 표시됩니다)

- 한 개만 고르면 그 챕터만 나옵니다.
- `전체 학습` 은 그대로 25챕터 573단어를 한 번에 봅니다.
- `선택 해제` 로 고른 것을 한 번에 지웁니다.
